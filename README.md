# 【项目名称】社区智慧养老服务微信小程序

> 说明：文中带 `【】` 的内容为占位符，发布或提交前请按实际情况替换；请勿在公开仓库中填写真实账号、密钥、个人路径等敏感信息。

## 一、项目概述

**【项目背景】** 面向社区居家养老场景，老年人及家属需要便捷的健康记录、生活服务预约与紧急求助渠道；社区工作人员需要统一的老人档案、服务派单与活动管理入口。

**【开发目的】** 通过「微信小程序 + 后端 API」的形式，在单仓库内完成老人/家属端与工作人员端的双端功能闭环，便于演示与课程或实训结题验收。

**【核心价值】** 降低老年人使用门槛（适老化界面、大字模式、操作引导），同时用统一接口与角色权限隔离保障数据与安全边界。

**【适配场景】** 适用于课程设计 / 综合实训 / 个人技术练手等初级规模项目：业务以演示与流程贯通为主，数据层可采用内存实现，后续可平滑替换为真实数据库。

## 三、环境搭建步骤（Windows）

以下命令均在 **PowerShell** 或 **CMD** 中执行，路径请替换为你的本机**项目根目录**（例如 `D:\code\Smart-Community-Elderly-Care-Mini-Program`）。

### 1. 环境准备

- 安装 **JDK 21**（与 `pom.xml` 中版本一致），配置 `JAVA_HOME` 与 `Path`。
- 安装 **Maven 3.8+**，确认命令行可执行 `mvn -v`。
- 安装 **微信开发者工具**，并准备小程序 **AppID**（测试可使用测试号，见注意事项）。

### 2. 依赖安装（后端）

```powershell
cd 【项目根目录】\backend
mvn clean install -DskipTests
```

若仅需运行、暂不打包全量测试，也可直接进入下一步启动。

### 3. 配置修改

| 配置项 | 文件位置 | 说明 |
|--------|----------|------|
| 后端端口 | `backend\src\main\resources\application.yml` | 默认 `server.port: 8126`，若被占用可改为其他端口（如 `8127`）。 |
| 小程序请求地址 | `miniprogram\app.js` 中 `globalData.apiBase` | 需与后端端口一致，例如 `http://127.0.0.1:8126/api`（修改端口后此处同步修改）。 |
| 小程序 AppID | `miniprogram\project.config.json` 等 | 填写你在微信公众平台获取的 AppID；勿将含密钥的私有配置提交到公开仓库。 |

**说明：** 当前仓库后端未使用 MySQL，**无需**配置 JDBC 连接字符串；若你自行扩展数据库，请在 `application.yml`（或 `application-*.yml`）中增加数据源配置，并保护好账号密码。

### 4. 项目启动

**启动后端：**

```powershell
cd 【项目根目录】\backend
mvn spring-boot:run
```

或在 IDE 中运行主类：`com.community.elderly.SmartElderlyApplication`。

**启动小程序前端：**

1. 打开微信开发者工具 → **导入项目** → 选择目录 `【项目根目录】\miniprogram`。
2. 填写 AppID（或选择测试号）。
3. 开发阶段在「详情 → 本地设置」中勾选 **不校验合法域名、web-view（业务域名）、TLS 版本以及 HTTPS 证书**（仅本地调试使用）。
4. 编译运行，在首页按提示选择 **老人/家属端** 或 **工作人员端** 进入对应流程。

### 5. 访问地址

| 用途 | 地址 |
|------|------|
| 后端 API 根路径（与 `app.js` 中配置对应） | `http://127.0.0.1:8126/api` |
| 小程序界面 | 在微信开发者工具模拟器或真机预览中访问 |

可用浏览器或 Postman 访问具体接口路径（如健康、活动等）验证后端是否正常（需符合各接口的请求方法与签名校验规则）。

## 四、核心功能详解

以下为业务功能概要，实现上采用 **Controller → Service → Repository（内存）** 分层；小程序端通过封装好的 `api` 发起请求，关键操作配合 **角色拦截与请求签名**。

### 老人 / 家属端

1. **个人与老人信息管理**  
   维护本人及关联老人资料，支持多老人切换与照片等字段；用于后续健康与服务数据的归属校验。

2. **健康监测管理**  
   录入血压、血糖、心率等数据并查看历史记录；结合规则做异常提示与简易风险等级展示（具体规则以后端与前端文案为准）。

3. **生活服务申请**  
   浏览可预约服务、提交申请、查看订单状态；评价与投诉入口与工作人员端处理流程衔接。

4. **紧急求助**  
   一键发起求助，后端快速响应并留存记录；接口可配置较短超时以提升「已发送」的感知速度。

5. **活动与社交**  
   查看社区活动、报名参与；支持简单互动发布，便于展示「社区运营」类场景。

### 社区工作人员端

1. **老人信息管理**  
   查看档案、风险标记等，与老人端上报信息联动（权限与可见字段受角色控制）。

2. **服务管理**  
   接单、派单、更新服务状态；可查看投诉相关入口，完成服务闭环演示。

3. **活动管理**  
   发布活动、管理报名人数；可提供导出类入口（若已实现）用于台账演示。

4. **求助处理**  
   接收求助类请求并记录处理结果，体现「事件驱动」工作流。

5. **数据统计分析**  
   对健康、服务类数据做汇总展示，支持按日/周/月等维度查看或生成报表入口（以实际页面为准）。

### 安全与体验（横切能力）

- **角色权限**：老人端与工作人员端接口隔离，避免越权访问。  
- **隐私字段**：敏感信息加密存储、传输与展示最小化（具体字段以后端实现为准）。  
- **请求签名与时间窗**：降低篡改与重放风险。  
- **适老化**：大字模式、主题区分、操作引导等，降低老年用户学习成本。

## 五、项目复盘总结

### 1. 开发过程中遇到的核心问题（示例，请结合个人经历改写）

**问题 A：前后端联调失败（请求失败或返回非预期）**  
小程序真机或工具中请求报红，后端日志无记录或返回 403/404。

**问题 B：数据「重启就没了」或「两个人看到不一致」**  
初期未区分全局状态与接口数据源，或误以为已接数据库，实际为内存存储导致体验与预期不符。

**问题 C（可选）：需求理解偏差**  
例如将「评价」与「投诉」混为同一状态机，后期返工调整页面与接口字段。

### 2. 问题解决方案（示例思路）

**针对问题 A：**  
- 先确认 `app.js` 中 `apiBase` 与后端端口、`/api` 前缀一致；本机防火墙是否放行端口。  
- 在微信开发者工具中打开「不校验合法域名」用于本地 HTTP 调试。  
- 对照浏览器/Postman 能否直接调通同一 URL；若 Postman 通而小程序不通，重点查域名、TLS、请求头与签名参数是否一致。  
- 查看 Spring Boot 控制台与小程序 Network 面板中的状态码与响应体，逐层缩小是网络层、鉴权层还是业务参数错误。

**针对问题 B：**  
- 明确文档中「内存 Repository」的定位：演示环境足够，生产需持久化。  
- 统一「单一数据源」原则：列表与详情以接口返回为准，避免仅靠前端缓存。  
- 若课程要求持久化，制定迭代计划：引入 MySQL + 迁移脚本，替换内存实现并保持接口契约稳定。

**针对问题 C：**  
- 对照 `docs` 下需求/设计文档做用例清单，与接口字段表对齐后再开发；小步提交，每完成一个用例自测一条完整路径。

### 3. 个人收获与不足（请按真实感受填写）

**收获示例：** 熟悉了微信小程序页面结构与生命周期、全局状态与分包组织；掌握了 Spring Boot 起服务、编写 Controller 与分层结构；理解了基于角色与签名的简单安全模型；对适老化与异常提示有了产品向思考。

**不足示例：** 对 Spring Boot 高级特性（如统一异常处理、校验注解、测试覆盖率）运用仍浅；SQL 与索引优化尚未在本项目中实践；对微信审核规则与正式环境域名的经验不足。

### 4. 后续优化方向（可落地清单）

- 引入 **MySQL**（或其他数据库），将内存 `repository` 改为持久化实现，并补充初始化脚本。  
- 补充 **全局异常处理** 与规范错误码，前端统一 Toast/弹窗展示。  
- 对核心 Service 编写 **单元测试**；对关键接口编写集成测试。  
- **SQL / 查询优化**：分页、索引、避免 N+1（在引入 ORM 后逐项落实）。  
- 配置 **HTTPS** 与合法域名，按微信要求关闭调试期「不校验域名」选项，走向可上架版本。  
- 完善 **日志与审计**（关键操作留痕），便于运维与问题追溯。

## 六、注意事项

### 运行常见问题

| 现象 | 可能原因 | 处理建议 |
|------|----------|----------|
| `mvn` 不是内部或外部命令 | 未安装 Maven 或未加入 Path | 安装 Maven 并配置环境变量，重新打开终端。 |
| 后端启动报端口占用 | 8126 已被其他程序占用 | 修改 `application.yml` 端口，并同步修改 `miniprogram\app.js` 的 `apiBase`。 |
| 小程序请求失败 | 本地 HTTP、域名未白名单 | 开发阶段勾选不校验域名；正式环境需 HTTPS 与合法域名配置。 |
| JDK 版本报错 | 本地 JDK 与 `pom.xml` 不一致 | 使用 JDK 21，或在团队中统一降级并修改 `pom.xml`（需全员一致）。 |
| `mvn clean install` 依赖下载慢 | 网络或默认仓库慢 | 配置国内 Maven 镜像源（settings.xml）。 |
