# 社区智慧养老服务微信小程序 - 设计文档

## 1. 项目架构设计

项目采用“前后端分离 + 三层架构”：

- 前端：微信小程序（双端角色共用一套工程，页面按角色划分）
- 后端：Java Spring Boot
  - Controller：接口层，处理路由与入参
  - Service：业务层，处理业务规则与数据转换
  - Repository：数据访问层（当前为内存实现，便于快速运行）
- 通信协议：HTTP JSON

### 1.1 目录结构

- `backend`：后端服务
  - `controller`、`service`、`repository`、`security`、`config`
- `miniprogram`：微信小程序
  - `pages/elder`：老人/家属端页面
  - `pages/staff`：社区工作人员端页面
  - `api`：接口调用封装
  - `utils`：请求、权限、签名、缓存、UI模式工具
- `docs`：项目文档

## 2. 双端模块设计

### 2.1 老人/家属端模块

- 信息管理模块：个人信息维护、多老人切换
- 健康管理模块：健康录入、记录查看、预警与风险评估
- 服务申请模块：预约、状态查看、评价投诉
- 紧急求助模块：一键求助、记录留存
- 活动社交模块：活动查看、报名、互动发布
- 适老化模块：一键大字模式

### 2.2 社区工作人员端模块

- 档案管理模块：老人档案查看与风险标记
- 服务管理模块：派单与状态流转
- 活动管理模块：发布、报名管理、导出入口
- 求助处理模块：接收并处理紧急求助
- 统计分析模块：核心指标统计与报表入口

## 4. 数据流程设计

## 4.1 通用请求流程

1. 页面调用 `api/*` 接口函数。
2. 统一进入 `utils/request.js`。
3. 自动附带角色头、时间戳、随机串、签名。
4. 后端拦截器进行签名校验、权限校验。
5. Controller -> Service -> Repository 完成处理并返回。

### 4.2 典型流程一：健康录入与预警

1. 老人端录入健康数据。
2. 前端执行轻量异常判断（血压/血糖/心率阈值）。
3. 异常时即时提示“健康预警”。
4. 数据提交后刷新列表并计算风险等级（低/中/高）。

### 4.3 典型流程二：紧急求助协同

1. 老人端提交位置与求助信息。
2. 后端写入求助记录并返回结果。
3. 工作人员端实时查看记录并更新处理状态。
4. 处理留痕用于后续统计与追溯。

## 5. 安全与性能设计要点

- 安全：
  - 隐私字段加密存储（Service 层写入加密、读取解密）
  - 角色权限拦截（按接口粒度控制）
  - 请求签名与时效校验
- 性能：
  - 前端 GET 短时缓存减少重复请求
  - 接口超时策略控制页面响应
  - 后端并发容器提升并发场景稳定性
