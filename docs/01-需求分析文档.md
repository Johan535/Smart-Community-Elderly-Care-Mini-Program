# 社区智慧养老服务微信小程序 - 需求分析文档

## 1. 项目背景

随着人口老龄化程度持续提升，社区居家养老场景对“便捷服务、及时响应、统一管理”提出了更高要求。传统模式中常见问题包括：

- 信息分散：老人档案、健康记录、服务记录分散，难以统一管理。
- 服务不透明：老人和家属难以实时了解服务预约、接单、处理状态。
- 紧急响应慢：求助信息传递链路长，缺少统一留痕与协同机制。
- 运营分析弱：社区工作人员缺少可视化统计和周期报表支撑决策。

本项目目标是建设一套“老人/家属端 + 社区工作人员端”的微信小程序，提供养老服务闭环能力，提升社区养老数字化管理水平。

## 2. 功能需求

### 2.1 老人/家属端

- 个人与老人信息管理  
  维护老人基础信息，支持多老人切换管理，支持老人照片上传。
- 健康监测管理  
  录入健康数据，查看历史记录，支持提醒字段；提供异常预警与简易风险评估。
- 生活服务申请  
  浏览/提交服务预约，查看订单状态，填写评价与投诉建议。
- 紧急求助  
  一键发起求助，提交位置与求助信息，保留求助记录。
- 活动与社交  
  查看活动、报名活动、发布互动内容。
- 适老化创新功能  
  支持一键大字模式，降低老年用户阅读和操作门槛。

### 2.2 社区工作人员端

- 老人信息管理  
  查看档案，标记风险老人，进行重点关注。
- 服务管理  
  接单派单、状态更新、投诉处理入口。
- 活动管理  
  发布活动、管理报名、导出数据入口。
- 求助处理  
  实时查看求助记录、更新处理状态与处理说明。
- 数据统计分析  
  查看核心指标，生成日/周/月报入口。

## 3. 非功能需求

### 3.1 性能需求

- 页面加载响应目标：3 秒内。
- 一键求助响应目标：1 秒内（前端快速提交策略）。
- 支持多用户并发访问不卡顿（后端并发数据结构优化）。

### 3.2 安全需求

- 老人隐私字段加密存储（姓名、病史、过敏史、紧急联系人、照片地址）。
- 严格角色权限控制（老人/工作人员边界明确）。
- 请求签名与时间窗校验，降低篡改与重放风险。

### 3.3 可维护性需求

- 前后端分层清晰，模块职责明确。
- 接口、工具、页面按功能拆分，便于扩展和维护。
- 命名统一、注释清晰、文档可直接用于展示与交付。
